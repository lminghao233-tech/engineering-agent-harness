# Security boundary

The API and model adapter are trusted services for one authenticated team. Bind API to loopback by default. Put a TLS reverse proxy and rate limits in front of any remote access; keep the Bearer token secret. There is no enterprise SSO or multi-tenant isolation. Anyone with the team token can create/cancel/review tasks. Reviewer names are operator assertions, not verified individual identities.

Only the trusted host worker broker holds Docker access and the model key. The Docker group is equivalent to privileged host access: restrict this service account and do not expose the broker to task code. API containers do not mount the Docker socket. Task subprocesses only run inside Docker, as a non-root user, with no network, no capabilities, a read-only root filesystem, read-only source, bounded temporary writable filesystems, CPU/memory/PID/file-size/output/time limits. A disposable tmpfs copy is used for testing. No dependency installation is exposed to the agent. Operator-prepared images must include dependencies under `/opt/venv` and must be pinned by digest. Containers alone do not defend against kernel vulnerabilities; use a dedicated patched Linux host for untrusted repositories.

Model tools cannot choose commands, images, credentials, test flags, host paths, or container options. Host-side repository processing only handles bytes and bounded ZIP extraction; it never imports repository modules, executes hooks, or runs repository setup. `.git` is never exposed. Symlinks and junctions are rejected. Source changes use hash preconditions, operation IDs, atomic file replacement and fencing checks under a SQLite write lock. Tests/configuration are protected by policy and checked before clean verification. An adversarial patch can still game public tests: final tests passing is evidence, not a proof of general correctness. Official benchmark scoring is a separate trusted operation.

Gold patches, test patches, FAIL_TO_PASS and grading scripts reside under `data/evaluator-only`, outside every task mount and model context. Do not grant the worker task user access to this host directory. Do not copy evaluator-only data into API images. The authenticated API rejects answer fields. Independent original repository tests remain in the verification baseline; model-created repro code is not the only acceptance signal.

Recoverable: task state, verified source snapshots, context, budgets, confirmed writes. Not recoverable: arbitrary process memory, external side effects, in-flight model outputs, or exact nondeterministic generation. Tool subprocesses have no network and disposable writable state. Model requests can remain pending until the 60-second HTTP deadline after cancellation; their conservative token reservations are retained. A crash during model response recording may lose provider usage evidence; it does not refund reserved budget.

Production release is gated on a real Linux Docker integration run, a real configured model run, official evaluation attempt, browser QA, infrastructure monitoring, backup restore drill, and operator review. See `docs/ACCEPTANCE.md` for actual status. Report vulnerabilities privately to the repository owner. Do not put credentials or customer code in a public issue.
