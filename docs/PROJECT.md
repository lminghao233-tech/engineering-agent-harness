# 技术总结与项目介绍

本平台将公开GitHub问题的输入、单Agent行动、工具执行、持久化状态、独立验证与人工审核串成一个可查询的执行过程。核心工程贡献是事务状态机、带fence的worker租约、操作ID与前后哈希核对、工作区检查点、受约束容器broker和评分材料分离。代码仓库、issue和工具输出都是任务数据，不具有修改平台权限的效力。

相较只保存对话或step编号，恢复协议明确区分文件已经改变、尚未应用和无法解释的结果。实际故障测试在文件原子替换后直接退出独立进程，保留PENDING意图，由新worker根据文件哈希确认动作。这证明支持场景下的恢复行为，不扩展为任意外部副作用的一次且仅一次保证。

执行工具不提供任意shell；可信broker根据固定模板启动非root、无网络、只读源码、受限tmpfs的Docker测试容器。宿主只处理源文件字节。独立验证重新构建干净目录，保护原始测试；官方SWE-bench另由可信评测环境执行。这些设计减少提示注入和评分污染途径，但不声称单靠容器或公开测试可以证明补丁安全。

本次实际失败和修复：系统Python3.13二进制依赖兼容失败后切换附带Python3.12；测试沙箱的临时目录与loopback权限问题通过工作区basetemp和授权的测试执行解决；执行尝试INSERT占位数错误被集成测试发现并修复。真实模型和Docker缺失导致公开任务阻塞，这不是修复失败率或官方模型成绩。

主要瓶颈：全量快照与目录hash为O(文件数/源码体积)；SQLite写事务会串行阻塞；单worker限制吞吐；模型请求取消存在最长HTTP超时窗口；仓库依赖镜像需要操作者准备；pytest-only工具不足以覆盖所有上游测试系统；全局存储配额、保留策略、监控和团队身份审计仍需补齐。下阶段优先执行Linux真实任务、完成目标仓库依赖镜像和官方评测，然后依据实测证据优化。

项目介绍可表述为：**构建单团队研发Agent执行平台，提供任务控制台、持久化恢复、受控工具、独立验证与公开基准实验管线。以固定数据清单和可审计事件连接任务、补丁、测试及审核，显式区分工程测试、真实模型任务和官方评测状态。**
